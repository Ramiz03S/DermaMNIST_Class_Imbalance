## Project: Can a Small Diffusion Model Fix Class Imbalance in Medical Images?

Rare classes in medical datasets have few examples, so classifiers tend to ignore them. The project tests whether images generated by a diffusion model help a classifier on DermaMNIST (skin lesions), and whether the generator simply copies its training images.

### Milestone 1 – Reproduce two published results

Part A – The classifier

1. Clone the MedMNIST experiments repository and install the `medmnist` package.
2. Use the repository's PyTorch training script to train ResNet-18 on DermaMNIST at 28×28 pixels. The data downloads automatically.

Target: AUC 0.917 and accuracy 0.735 on DermaMNIST.

Part B – The diffusion model

1. Load the released DDPM model for CIFAR-10 (`google/ddpm-cifar10-32`) with the DDIM pipeline in the `diffusers` library.
2. Generate 50,000 images with 50 sampling steps. Generate them in batches and save them to Drive as you go.
3. Compute the FID score against the CIFAR-10 training set with the `clean-fid` package.

Target: FID 4.67 with 50 steps (the DDIM paper also reports 4.16 with 100 steps). Small differences between FID implementations are normal; explain them.

### Milestone 2 – Improve

- Train a class-conditional diffusion model on DermaMNIST (start at 28×28 pixels).
- Use it to generate extra images for the rare classes, retrain the classifier, and compare with class-weighted loss and oversampling.

### Milestone 3 – Contribute

- How many synthetic images help before they start to hurt?
- Does the generator copy training images? Check with a nearest-neighbour search.
- Is diffusion better than simple augmentation at the same compute cost?

### Watch out

- A 2024 audit found data-quality problems in DermaMNIST and released corrected versions. Read it before you trust your split.
- Train the generator on the training split only.

## Part B — DDIM sampling and FID on CIFAR-10

Reproduces the DDIM paper's CIFAR-10 result: **FID 4.67 with 50 sampling steps**.

### Method

1. Load a pretrained DDPM CIFAR-10 U-Net and its beta schedule through `diffusers`.
2. Generate 50,000 images with 50 deterministic DDIM steps (η = 0), in 200 batches of 250. Batch *i* uses seed `1000 + i`, and each batch is saved to Drive as `.npy`, so a disconnected run resumes from the last saved batch.
3. Convert the batches to PNG on the local Colab disk.
4. Compute FID against the CIFAR-10 training set with `clean-fid`, in both `clean` and `legacy_tensorflow` modes.

### Implementation choices

**Quadratic timestep spacing.** The `diffusers` `DDIMScheduler` only supports linear spacings, while the paper's CIFAR-10 results use quadratic spacing, which puts more steps at low noise levels. The notebook therefore samples with `generalized_steps` from the [official DDIM repository](https://github.com/ermongroup/ddim), using the paper's sequence:

```python
seq = [int(s) for s in np.linspace(0, np.sqrt(1000 * 0.8), 50) ** 2]
```

**EMA weights.** The `google/ddpm-cifar10-32` checkpoint holds raw (non-EMA) weights, whereas the DDPM and DDIM papers evaluate with EMA weights. This is documented in a [Hugging Face discussion](https://huggingface.co/google/ddpm-cifar10-32/discussions/10), where users report FID ≈ 12 with this checkpoint and the Diff-Pruning authors share the [official EMA checkpoint converted to diffusers](https://github.com/VainF/Diff-Pruning/releases/download/v0.0.1/ddpm_ema_cifar10.zip). Both are evaluated with the same procedure; choose one with `weights_origin = "ema"` or `"google"`.

### Results

50,000 samples, 50 DDIM steps, quadratic spacing, compared against CIFAR-10 train:

| Weights | FID (clean) | FID (legacy TF) |
|---|---|---|
| EMA (converted official) | 5.59 | **4.72** |
| `google/ddpm-cifar10-32` (non-EMA) | 11.89 | 9.79 |
| **DDIM paper** | – | **4.67** |

With EMA weights, the legacy FID is within 0.05 of the paper. The remaining gap is consistent with sampling noise (a different set of seeds) and 8-bit quantization of the samples. The non-EMA checkpoint scores roughly twice as high, matching the reports above.

**Clean vs legacy FID.** `legacy_tensorflow` reproduces the original TensorFlow Inception pipeline used by the DDPM/DDIM papers, so it is the number to compare with 4.67. `clean` resizes to 299×299 with proper antialiasing; it is a more correct measurement but is not comparable to published legacy numbers.

### Running

Generation resumes automatically after a disconnect; FID takes about 4 min per mode. Outputs go to `Milestone_1_b/{ema,google}/run_0/ddim50_batches`.

### Functions

DDIMPipeline.from_pretrained(model_id).to(device)
Loads the U-Net weights and scheduler config, either from the local EMA folder or from google/ddpm-cifar10-32, and moves the model to the GPU. Here the pipeline is just a container, its own sampling loop is not called.

generalized_steps(x, seq, model, betas, eta=0.0)
Runs the DDIM sampler, walking the timestep sequence from high noise to low. At each step it predicts the noise, estimates the clean image, and jumps to the next timestep with the DDIM update rule. With eta=0 no fresh noise is added, so sampling is deterministic. It returns two lists, the intermediate states and the predictions.

fid.compute_fid(folder, dataset_name="cifar10", dataset_res=32, dataset_split="train", mode=mode)
Runs every image in the folder through an Inception network and fits a Gaussian to the features. It then computes the FID to the precomputed CIFAR-10 train statistics. mode="clean" uses antialiased PyTorch resizing. mode="legacy_tensorflow" uses the original TF pipeline, so that number is the one comparable to the paper's.
